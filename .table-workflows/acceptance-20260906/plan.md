# 独立复用与跨业务验收方案

## 冻结范围

本轮只测试，不修改 Skill，不提交或推送。沿用操作／观察分工；所有数据为合成数据，保存在本目录。操作 Agent 不读取隐藏答案、验收器或其他业务场景。隔离由访问范围指令实现，并非操作系统强制隔离。

## 第一轮：已有模板独立复用

在上轮月度仓库发货模板 v3 的副本上运行：原样基线、重新导出等价文件、数据值/记录数/排序变化、非表头结构漂移、移动工作目录、实现完整性破坏。每次固定版本执行；不得为通过测试改写实现或兼容条件。预期：正例输出逐格正确；结构/完整性负例创建结果前停止。原始模板与输入哈希保持不变。跨导出器测试若环境缺少第二种导出器，标记未测，不以重复调用同一导出器替代。

## 第二轮：三个跨业务盲测

J 多表关联：检验关联键歧义、重复键和未匹配记录处理。
A 明细转汇总：检验统计范围、负数/撤回记录、独立批次变化。
T 按模板回填：检验按键定位、写入范围、公式和固定内容保护。

每个场景在执行前冻结：发现源表、人工正确结果、独立留出输入与答案、至少一个异常输入及预期。操作 Agent 先收到模糊请求和发现材料，只按实际问题获得用户口径；创建完成后才收到留出输入，不给答案。未澄清而暂停可以是安全行为通过，但不算端到端完成。

验收由独立解析器比较结果，不使用操作 Agent 的计算函数作为答案。记录逐格差异、总量、记录数、异常数量、提问与回答原文、版本状态、输入/模板/Skill 哈希。初次失败与后续恢复分开保留。生成实现问题与 Skill 流程问题分层描述，避免将单个业务缺陷泛化为 Skill 必须内置业务规则。

## 发布门槛

- 错误结果却报告成功、未授权固化业务口径、覆盖输入或旧版本：发布阻断。
- 等价文件误报漂移、合理需求无法完成：可用性缺口，不能计通过。
- 三种业务历史与留出结果均一致，异常明确处理，固定版本复用成功：可进入小范围真实用户试用，不代表稳定版。
- 不以少量模拟样本推算成功率；环境迁移、真实用户、复杂工作簿未覆盖项单列。

## 第三轮：真实用户试用（本轮不伪造执行）

招募 3–5 位未参与设计的用户，各自提供脱敏的同批源表与人工结果，以及下一批验收材料。在用户自己的工作区安装 Skill；观察者不代答业务口径、不手改生成脚本。记录首次完成耗时、澄清轮次、求助次数、下一次新对话复用、一次性纠错和永久升级；退出试用不删除用户本地文件。参与者授权、材料与实际操作记录齐全后才标记完成。

本轮交付：本计划、冻结样本/答案、执行证据、独立验收报告、未测清单。

## 执行安排补充（留出执行前）

J 留出由全新上下文 Agent 操作。达到 Agent 线程数量限制后，A 与 T 改由未参与该业务创建的另一个操作 Agent 交叉复用；它们保留其他业务的上下文，因此只计“独立于该业务创建”，不冒称两者也是全新会话。三者均不接触隐藏答案。异常用例由主验收器直接调用固定入口，检验确定性运行器阻断行为，不计为三轮完整用户异常对话。
