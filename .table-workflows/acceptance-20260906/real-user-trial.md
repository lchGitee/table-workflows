# 小范围真实用户验收单

状态：尚未招募、尚未执行。模拟 Agent 不计为真实参与者。

## 准备

选择 3–5 位未参与 Skill 设计、日常会重复处理表格的用户，覆盖至少两种不同业务。由用户确认材料可用于测试并自行脱敏。只在用户本地工作区保存业务规则；不将数据、模板或凭据上传公共仓库。

每人准备历史源表、同批人工正确结果，以及另一批未用于推导的源表和正确答案。若有固定结果模板，一并提供。记录 Skill 文件哈希、系统/Agent/运行时版本和安装方式；用户业务答案不写入 Skill。

## 操作顺序

1. 用户自行阅读安装入口并安装。观察者只记录卡点，不能代替修依赖或解释专业术语。
2. 用户用自己的话描述重复任务，分批提供文件。Agent 必须基于已看到的材料澄清；观察者不得预先补充完整规则。
3. 用户核对首轮结果与规则说明；保留未确认项。用独立答案逐格验收，记录公式、保护区域及汇总。
4. 换新对话，用户提供下一批输入，固定版本运行。此时才对照留出答案。
5. 用户提出一次性改动，然后提出明确的长期政策改变。检查临时结果不污染规则、长期升级保留旧版、回归失败不发布。

## 每位参与者记录字段

参与者匿名编号、业务类型、授权时间、环境、初始需求原文、每轮问答、首次完成耗时、澄清轮数、重复提问数、用户求助数、观察者介入内容、安装是否成功、历史差异数、留出差异数、异常数、误报成功次数、源文件哈希是否不变、临时/长期版本检查、用户能否自行找到下次调用方式。

## 判定

- 未介入且创建、留出复用、纠错均通过：该用户场景通过。
- 用户还无法说明关键口径，Agent 正确暂停：安全交互通过，端到端未完成，不能按成功用户计数。
- 观察者修改脚本或代答后才完成：保留恢复结果，但初次自助流程不通过。
- 错结果报告成功、未确认规则长期生效、覆盖输入或旧版：阻断对外稳定发布。

记录人数与场景原数，不据 3–5 人的小样本宣称总体成功率。完成这一轮后，再决定是否扩大试用。
