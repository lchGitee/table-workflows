## 提问与确认来源

三份 `case-*/dialogue.md` 都包含初始材料角色、实际问题及主 Agent 转达的模拟用户回答；回答与事先冻结政策相符，没有将初始材料中的偶然关系直接当规则。

- J 明确询问编号/名称关联歧义及空键、未匹配、主表重复。回答还纠正了候选“沿用订单名称”为“客户主表名称优先”。留出确实打破同名关联，但没有名称源内容互相冲突的记录，因此名称优先的行为覆盖仍有限。订单号重复未在实际问题中确认，也未在冻结异常中测试，不能声称完整覆盖该政策。
- A 明确询问按状态还是正负筛选、负数和零、未知状态、排序及部门范围，均收到回答。重复记录编号没有业务处理授权；对其停止询问属于安全处理通过，不能声称已确定永久去重或重复业务规则。缺失部门、非数值工时同样被声明为待确认异常，本轮未测。
- T 明确询问按编码、写入数量、重复、未知项目、缺失项目，回答完整规定停机、缺失填零与其他内容保留，覆盖与结果一致。

## 六个真实异常

已审阅 `anomaly-results.json` 中完整回执。每项先得到输入及模板结构 MATCH，再触发下表异常；并非缺依赖、结构误报或命令故障导致的伪通过。每项退出 1，异常数量 1，业务结果不存在。

| 场景 | 实际阻断原因 | 解释 |
| --- | --- | --- |
| J duplicate | 客户主表编号重复：C01 | 命中已确认重复主键政策 |
| J unknown | 订单未匹配客户，数量：1 | 命中已确认未匹配政策 |
| A duplicate | 第 3 行记录编号重复，需确认 | 安全暂停；未擅自固化去重政策 |
| A unknown | 第 2 行状态未确认，请用户确认 | 命中已确认未知状态政策 |
| T duplicate | 编码缺失或重复，请确认 | 本输入实际为重复，命中政策；提示可更具体但不影响判断 |
| T unknown | 需求出现计划表没有的项目，请确认 | 命中已确认未知项目政策 |

三份创建验证报告均有真实普通数据/记录数变化正例与非表头合并漂移负例，后者创建输出前停止。独立审阅采用这些实际运行回执作为执行证据；本次未另外再次执行结构变体。

## 契约与发布范围

主审计 `audit.json` 显示三个 Manifest 均通过完整 JSON Schema 校验，所有执行产物哈希与版本快照匹配、19 份冻结工作簿哈希不变，原 Skill 及既有模板未改。操作方创建时明确披露未找到 Schema 校验器，主审计后续补足机器校验，没有伪报。

三个 Manifest 均保留 TRIAL，合理：正常运行方没有收到隐藏人工答案，未擅自提升状态。观察者独立验收通过可作为后续晋级证据，但本轮未修改 Manifest。

目录为 `case-J/order-ownership`、`case-A/department-hours`、`case-T/service-plan`，均未采用案例工作区下 `.table-workflows/<workflow-id>` 默认形式。初始用户只明确授权“复制到本案例目录用于回放”，未明确指定任务模板子目录；本轮另有隔离写入范围约束。应记为默认存储/自动发现契约未闭环：已证明给定任务目录能复用，未证明纯名称能在默认规则库扫描发现这些目录。不能将隔离测试下的目录选择直接泛化为数据安全违例，也不能声称默认目录发现通过。

本轮跨业务发布门槛在所测业务范围内满足，可以进入小范围真实用户试用；仍应保留默认目录发现、真实用户、真实办公软件与复杂对象等未测范围。没有根据三个合成案例推算成功率，也没有将安全暂停计为异常业务已完成。
