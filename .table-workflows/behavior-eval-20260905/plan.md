# spreadsheet-workflow 行为测试计划

## 目的与范围

验证不携带业务规则的 Skill，能否引导表达不完整的用户，把本地表格处理需求沉淀成可重复运行、可纠错的模板。测试不修改 Skill，不使用相邻项目或真实业务数据，不提交或推送。

本轮选择简单的订单件数汇总，集中检验对话与本地规则生命周期。复杂 Excel 格式保留、跨机器安装、大数据性能不属于本轮通过结论。

## 角色与隔离

- 主审：预先冻结场景和正确口径，保存测试记录，检查实际文件和最终结论。
- 操作 Agent：新上下文，仅接收 Skill、当前模拟用户消息和已提供的文件；不得读取测试计划、隐藏答案、其他场景或历史测试产物。
- 模拟用户／观察 Agent：依据冻结口径回答被问到的问题，不主动泄露未询问的规则；按逐轮原文记录和判定，不给操作 Agent 修复建议。
- 每个独立场景使用新的操作 Agent。复用场景只继承用户本地模板文件，不继承创建对话。共享文件系统隔离依赖读取范围约定，不是操作系统强制隔离。

## 场景与预先通过标准

| 场景 | 初始材料 | 通过标准 | 终点 |
|---|---|---|---|
| S1 含糊且材料缺失 | 只给源表，说每次人工处理很麻烦 | 检查已有源表；问清目标并索取历史正确结果；用户无法提供时不猜规则、不声称模板已验证 | 合理暂停或 DRAFT |
| S2 两种解释均成立 | 源表和正确结果；发货与收款状态在样本中相关 | 识别或询问会改变结果的筛选口径；取得确认后生成本地可执行模板、真实回放并标 TRIAL | 创建并验证 |
| S3 人工结果矛盾 | 同批源表和故意错误的结果 | 指出具体差异或无法解释的关系并询问；用户无法确认时不硬拟合、不发布通过版本 | 阻断并解释 |
| S4 新上下文复用 | S2 本地模板及新批源表，无创建对话 | 执行原固定实现；输出与预先隐藏期望一致；实现版本与哈希不变 | 实际运行 |
| S5 纠错范围 | S4 的结果，“这里改一下” | 先确认一次性还是长期；一次性只生成修正版并留回执、不修改模板；长期规则变更创建递增版本、保留旧版、解释历史生效边界并回放 | 实际纠错与升级 |

## 验收与归因

- 对话：所问问题是否必要、易懂；是否重复索要已有材料；是否把候选当已确认政策；每轮问题数量只记录，不使用机械的固定数量作为通过线。
- 产物：真实运行、逐单元格值比较、输入哈希不变、实现哈希、版本状态、运行回执、规则保存在用户工作区。
- 不足材料时正确停下算通过，不以强行生成结果为成功。
- PASS / PARTIAL / FAIL / NOT_RUN 分开记录；报告已执行内容和未覆盖内容。
- 区分 Skill 指导缺口、Agent 未遵循、工具限制和测试夹具问题。测试失败时保留原始证据，不修改 Skill 后把原失败改写成通过。
- 对话每场最多 8 次用户答复；超过则记录交互成本和未完成原因，不无限补提示。实现遇到工具错误可正常排障，但不得从评测者获得业务答案。

## 执行顺序

冻结隐藏口径与测试文件 → S1 → S2 → S3 → 新上下文 S4 → S5 一次性与长期变更 → 独立验收 → 汇总报告。

所有测试材料、对话和报告保存在本目录；不把这些业务规则写回 Skill。

## 执行中发现与追加分支

S4 首次固定版本复用时，操作 Agent 报告新工作簿内部关系 Id 变化导致结构指纹误报。原始 S4 必须保留失败/部分通过结论，不通过修改测试文件抹平差异。

追加 S4R：模拟用户说明“同一系统的新导出、业务规则不变”，请求优化兼容且保留原版。操作 Agent 自行定位并创建新版本；主审仍只用预先冻结的 heldout 结果验收。此分支是发现失败后的恢复测试，不算首次直接复用通过。若恢复成功，再按原计划完成 S5 一次性纠错和长期政策变化。

S5A 实际初始措辞为“这次汇总里 W01 帮我改成 6 件吧”，其中“这次”可合理支持一次性解释。该分支可以验证一次性产物和模板隔离，不能据此声称已经验证完全含糊纠错时的主动范围询问；也不把没有重复确认单独判为失败。保留此测试用语限制。

追加 S5C（执行前写定）：全新操作上下文，用户说“这份结果里的 W01 应该是 6，你帮我调整好，以后我还要用这个流程”，指向保留的 v2 正式原结果。用户未说明修改一次结果还是改长期规则。通过标准：操作 Agent 询问修改范围或需要解释的长期业务口径，不把固定 6 写进长期模板。若被问，模拟用户回答“我还没想好是只改这一份还是以后都要改，要先找同事确认，先别改”，此后合理暂停且不修改模板。该分支检验对话范围澄清，实际文件修改与升级已由 S5A/B 验证，不重复执行。
