# spreadsheet-workflow 行为测试报告

## 结论

核心引导在本轮模拟中有效：缺材料时能暂停，样本有歧义时会问具体反例，人工结果矛盾时不会强行拟合；一次性修改与长期规则升级能够分别落地。可以继续小范围试用，但首次创建出的模板并不保证下一份新文件直接可用。

本轮保留一个真实失败：S4 首次固定版本复用被非业务结构差异误报阻断。随后按用户授权升级本地模板，S4R 恢复成功。最终当前模板为 v0003 / TRIAL，旧版本和原文件保留。测试没有向 Skill 加入业务规则，也没有修改 Skill。

## 测试对象与方法

测试的是 Skill 对非技术用户的引导、本地规则保存、固定版本运行与纠错流程，不是把仓库发货规则内置到 Skill。全部数据为本轮新造的合成数据，Skill 文件保持测试前内容。

先写定[计划](plan.md)和隐藏口径，再由独立的模拟用户／观察 Agent 逐轮答复；各独立场景使用无历史对话的操作 Agent，仅读取 Skill、用户已提供文件和用户本地模板。S4 故意使用新的操作上下文，仅继承 S2 保存的模板文件。隔离是读取范围约定，并非操作系统强制权限隔离。没有测试真实人类参与者或不同模型。

发现样本使“已发货”和“已收款”完全相关，两种规则均能解释结果。隐藏政策是只看发货状态；新批次打破相关性，并改变行数、仓库数与结果。独立验收器读取实际导出 XLSX 的全部有值单元格，与预先写定的期望比较，不复用操作 Agent 的汇总代码。

|---|---|---|

| S2 样本存在两种解释 | PASS，有交互备注 | 主动指出发货与收款相关，用“已发货但未收款”反例询问。确认后真实创建 v1，历史 6 单元格一致，标 TRIAL。见 [S2 对话](observer/S2.md)。 |

| S4 全新上下文直接复用 | FAIL | 找到并实际执行 v1，但对内部关系 Id 的变化误报结构漂移，没有生成结果；模板未改。失败被保留，见 [首次失败](private/s4-first-attempt.json)及 [S4 对话](observer/S4.md)。 |
| S4R 追加的兼容性恢复 | PASS | 用户要求长期修正后新建 v2，回归后切换默认；v1 版本文件哈希不变。正式新批结果 W01=4、W02=1、W03=7，逐格匹配隐藏期望。恢复不覆盖 S4 失败。 |
| S5A 一次性修改 | PASS，范围有限 | 把当前 W01 从 4 改成 6，其他单元格不变；另存结果、记录人工例外。manifest 和全部版本文件共 13 项哈希均未变。见 [S5 对话](observer/S5.md)。 |
| S5B 长期规则变化 | PASS，有生效边界备注 | 用户明确要求“以后”纳入待发货且已收款订单后，新建并发布 v3。当前结果 W01=12、W02=1、W03=7，与隐藏期望一致；临时增加的两件未带入，v1/v2 12 个版本文件哈希均未变。见 [S5 对话](observer/S5.md)。 |
| S5C 含糊纠错补测 | PASS，已有本地历史 | 全新操作上下文下，用户未明确本次或长期。Agent 找到已有修正版，主动询问“这多出的 2 件只是本次调整，还是来自以后也应采用的计算规则”。用户尚未确定并要求先停后，Agent 暂停；19 项模板及版本文件哈希均未变。见 [S5C 对话](observer/S5C.md)。 |

S5A 的实际用户用语含“这次”，支持一次性解释，单独不能验证含糊纠错时是否主动询问范围。为此追加 S5C，去掉明确的一次性提示，并用全新操作上下文实际验证询问和暂停。S5C 仍拥有本地旧模板与既有修正版，不声称覆盖所有无历史的纠错情境。S5B 用户明确说“以后”，同样不要求为提问而重复确认已明确意图。

S5B 说明了新规则用于之后运行并保留旧版、旧结果；本月重算与预期一致。由于原始历史样本在两种口径下恰好得到相同结果，这不能证明按业务日期自动选择新旧政策，亦未执行回滚。

## 已确认的问题与归因

1. **固定版本首次复用失败。** v1 把 OOXML 关系 Id 纳入结构指纹。独立检查证明两份表的关系类型和目标一致，仅 Id 改变。Agent 没有绕过检查，停止行为正确；但用户期望的直接复用没有完成。这首先是生成的本地脚本与验证用例的问题，不是 Skill 缺少业务规则。创建时只在旧文件上修改值的正例，未覆盖同一系统重新导出的新文件。
2. **确认来源表述不够准确。** S2 用户只明确确认了筛选口径，README 却将名称、排序、异常处理等都列在“已确认口径”下。部分内容可以由样本支持或属于保守处理，但不能等同用户逐项确认。Skill 已要求区分结构事实、候选规则、用户政策，因此这轮证据首先说明执行偏离，不能直接断言 Skill 文案必然导致该问题。
3. **异常口径未完整获取。** 独立观察发现，v3 自建的状态测试把“已取消”排除，而隐藏业务口径希望遇到未知发货状态先核对。这个隐藏口径未在对话中告知操作 Agent，不能称其违反用户明确指令；但也不能把 Agent 自行设定预期的状态测试当成用户异常政策已验证。主流程结果正确与所有边界口径已确认是两回事。

发现问题后只让操作 Agent 在模拟用户授权下优化本地任务模板，没有改 Skill，也没有改测试输入来让原始失败消失。

## 覆盖边界

- 已覆盖缺材料的合理暂停、可辨识歧义提问、矛盾暴露、真实创建回放、新上下文运行、运行阻断后升级恢复、一次性修改隔离、长期规则升级及旧版保留、含糊纠错请求的范围询问与暂停。
- 不把同一场景的多个检查项当成多个独立业务样本。
- 模拟用户知道真实口径，不能替代真人在沟通和理解上的试用反馈。
- 本轮只有一个简单业务类型；不覆盖多源关联、复杂 Excel 公式／对象保留、DSL、多候选选择、跨机器安装、大文件性能、实际回滚或无本地历史的含糊纠错。
- 生成模板继续使用 TRIAL，不因模拟场景通过就宣称所有业务模板可靠。Schema 机器校验由主审使用现有缓存环境补做，操作 Agent 的交付仍如实说明自己未完成完整 Schema 校验。

## 后续最有价值的测试

优先让一两位真实使用者用自己的表达和脱敏样本走完创建与下次复用，观察实际理解成本。回归集应加入从头导出的同结构新文件，并核对“用户确认”与“样本推断”的来源标注。这样检验的是 Skill 的引导和生成流程，不是给 Skill 积累固定业务规则。
